=== CORE CONCEPT ===
A lesson is authored as an editable tree (lesson → pages → blocks).
PUBLISHING COMPILES that tree into an immutable JSON manifest stored on 
a version row. Students only ever consume a published manifest, never 
the live authoring rows. Pages own progression and completion rules; 
blocks own content. Navigation, progress indicators, and results 
display are PLATFORM behavior, never authored blocks.

=== CONVENTIONS ===
- No database enum columns. Status/type/rule columns are strings backed 
  by PHP enums with Eloquent casts.
- STABLE IDENTIFIERS: every item a student response can reference 
  carries a stable string ID generated as a ULID at creation:
  pages (page_id), blocks (block_id), quiz questions, quiz options, 
  vocab terms, matching pairs, hotspots, bank items, CER fields.
  page_id and block_id are GLOBALLY unique, not per-parent.
  Reordering anything must NEVER change a stable ID.
- Use application-level defaults for JSON columns. Do not rely on MySQL 
  JSON expression defaults unless you confirm the installed version 
  supports them.

=== 4. HTML SANITIZATION ===
Create App\Services\HtmlSanitizer wrapping symfony/html-sanitizer (or 
HTMLPurifier — tell me which you chose and why). Every author-supplied 
HTML field is sanitized DURING COMPILE, and only sanitized markup is 
stored in the manifest: rich_text.html, callout.html, 
video.transcript_html, short_response.prompt_html, 
short_response.rubric_html, cer.scenario_html.
Strip: script tags, event handler attributes, javascript:/data: URLs, 
iframes and embeds, style attributes, unsupported tags.
Allow: headings, paragraphs, lists, strong/em, links (http/https/mailto 
only, forced rel="noopener"), tables, br, blockquote, code.
Do not rely on render-time escaping — these fields intentionally carry 
markup. Test the policy.

=== 5. PUBLISH / COMPILE SERVICE ===
App\Services\LessonPublisher::publish(Lesson $lesson, User $user): LessonVersion

Must run inside a DB transaction and lockForUpdate() the lesson row 
before calculating the next version number. A failed publish must leave 
the lesson, its status, current_version, and all version rows unchanged 
— no partial writes.

Sequence: validate every block via its type's validateConfig() → 
sanitize HTML → compile each block → assemble manifest → create 
LessonVersion → set lessons.current_version, status=published, 
has_unpublished_changes=false → commit.

Manifest shape:
{ schema_version: 1, code, title, version, estimated_minutes,
  learning_target, success_criteria,
  pages: [{ page_id, title, position, completion_type, 
    estimated_minutes, settings,
    blocks: [{ block_id, type, config, grading }] }] }

Published versions are immutable — editing and republishing creates the 
next version.
